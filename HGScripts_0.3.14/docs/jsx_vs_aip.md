# JSX 脚本 vs AIP 插件：能力差异速查

> 整理于 2026-11-08，供闲时翻看。这里不写代码细节，只说「能做/不能做」和「为什么」。

## 先分清两个东西

HGScripts 里同一类功能，往往有两套实现：

- **JSX（脚本）**：改动快、部署轻，但能力被 Illustrator 的「脚本层」限制住。
- **AIP（C++ 插件）**：能力强，能干脚本够不着的事，但改动要重新编译、还要按年份各做一份。

下面按「卡点」来列差异。

---

## 1. 弹窗选颜色（最近踩到的坑）

脚本里唯一能用的弹窗选色是 `$.colorPicker()`，它有三个硬限制：

| 限制 | 说明 |
| --- | --- |
| 不是 Illustrator 自带拾色器 | 它弹的是一个简化选框，不是你在 Illustrator 里双击色板弹出的那个完整拾色器 |
| 只有 RGB | 只能拿回一个 RGB 值，选不到 CMYK / 色板 / 专色 |
| 没有吸管 | 不能从画布上直接吸取现成颜色 |
| 标题写死为「颜色」 | `$.colorPicker()` 不接受标题参数，弹窗标题是系统固定的，改不了 |

**结论**：脚本层弹不出「自带完整拾色器」也弹不出「带吸管的取色框」，这是脚本层的天花板，不是没做全。

- 想用完整拾色器 / 吸管？只能换 AIP（C++ 可以直接用宿主原生界面）。
- 想勉强绕一下？可以让你先用 Illustrator 自带吸管吸到前景色，脚本再读 `doc.defaultFillColor`，但交互变绕、多色排除很繁琐，而且「读得准不准」还要先验证。
- 试过用 ScriptUI 自建选色器（R/G/B 滑块 + HEX 输入 + 常用色 + 预览）：实测太简陋、质感远不如系统那个「颜色」框，已回退。ScriptUI 做不出原生拾色器「渐变场 + 色板网格」那种质感，这条路性价比低，不建议再试。

---

## 2. 改「外观面板」里的填色 / 描边

- **JSX**：只能改普通路径的 `fillColor` / `strokeColor`；挂在「外观(Appearance)面板」里的那条填色/描边**改不动**。
- **AIP**：用 SDK 的 ArtStyleParser 能逐条改外观里的 paint field，能处理复杂包装稿、编组外观填色。

这也是为什么有些复杂对象，JSX 看着「没反应」，AIP 却能改的原因。

---

## 3. 剪贴板

- **JSX**：没有可靠的原生剪贴板接口；借外部 PowerShell 代劳又慢又不稳。
- 需要「点击即复制」这类能力 → 用 CEP 面板或 AIP。

---

## 4. 右键菜单 / 控件

- **JSX（ScriptUI）**：普通文字控件分不清左右键，右键菜单不能原生做。
- **AIP**：Win32 界面能做完整控件、菜单、拖拽之类。

---

## 5. 画布绘制 / 海量对象

- **JSX**：适合少量对象的常规处理；对象特别多会变慢。
- **AIP**：C++ 快，也支持在画布上直接绘制（比如噪声生成器的画布预览）、实时拦截事件。

---

## 6. JSX 侧的其它已知限制

- 对象 `note` 不是加密存储，导出或被别的软件打开时可能被带出去，**别往里放敏感信息**。
- 图层本身存不了隐藏信息，只能挂到具体的对象上。
- 脚本尽量静默执行、不弹提示框（这是项目约定，不是做不到）。

---

## 7. 选 AIP 的「额外成本」

AIP 不是全能无代价，用它是为了换上面那些能力：

- 每年份要各编一份 `.aip`（2023 / 2024 / 2025 / 2026），不能只做一个通用。
- 部署要提权（插件目录普通用户只读）。
- 改了要重新编译、重新部署；而 JSX 改完刷新面板基本就能用。

---

## 8. 一句话怎么选

- 轻量改色、普通路径、快速迭代 → **JSX 够用**。
- 复杂外观填色 / 海量对象 / 实时 / 剪贴板 / 右键菜单 / 画布绘制 → **AIP**。
